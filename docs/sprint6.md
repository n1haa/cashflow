# Sprint 6 — интеграция браузерного интерфейса

## Результат и архитектура

До начала работ frontend, package.json, страницы, роутинг, компоненты и
API-клиент отсутствовали. Backend — FastAPI с Transaction и отдельными
результатами категоризации, регулярности, прогноза и разрывов. Данные — в памяти
экземпляра приложения. Все 305 тестов Sprint 1–5 проходили до изменений.
Оригиналы находятся во внешнем каталоге Telegram Desktop, а не в репозитории;
использованы те же файлы и контрольные суммы предыдущих спринтов.

До реализации выбран план: минимальный HTML/CSS/JS frontend в том же checkout,
выдача через FastAPI, один API-клиент, использование всех существующих endpoints,
раздельные состояния модулей и проверка обоих CSV через браузер. Нужных
незавершенных backend-модулей/отсутствующих endpoints не обнаружено. Главное
ограничение — отсутствие текущего баланса старых выписок и сохраненных метаданных
импорта в GET транзакций. Эти случаи адаптированы в отображении, контракты не менялись.

Создан одностраничный адаптивный интерфейс с навигацией по якорям, системными
шрифтами, светлыми панелями, темной навигацией, синим акцентом и отдельными
цветами поступлений/расходов/статусов. Готового дизайна не было. Тяжелые runtime
зависимости и сборщик не добавлялись. Backend менялся только для выдачи HTML и
статических файлов; алгоритмы Sprint 1–5 и их API сохранены.

## Функциональность и API

| Метод / путь | Данные и потребители |
| --- | --- |
| GET /api/transactions | Массив существующих Transaction; загрузка состояния при открытии |
| POST /api/transactions/upload | Multipart `file`; импорт, счетчики, ошибки, transactions/source_rows |
| POST /api/transactions/categorize | Метаданные по transaction_id; категории и объяснения в таблице |
| GET /api/transactions/recurring | Счетчики и groups; таблица периодов, статусов, средних, диапазонов и дат |
| GET /api/forecast | Summary, daily, categories, warnings; обзор, SVG и таблицы |
| GET /api/forecast/cash-gaps | Статус, gaps, ограничения; список дефицитов и связанных событий |

Пользователь выбирает или перетаскивает CSV/XLSX, видит имя и размер, запускает
загрузку. Форматы и предел 10 МиБ повторяют существующие ограничения backend;
проверка на клиенте не заменяет серверную. Ответ partial_success видим как
предупреждение с реальными ошибками строк. Показаны необязательный ИНН, источник
и исходная строка/operation_id, когда они доступны в ответе импорта.

Затем один запрос категоризации, после него параллельные запросы независимых
модулей. Повтор запроса относится к конкретному модулю, а изменение даты/баланса
обновляет только прогноз и разрывы. POST загрузки не дублируется. До завершения
запросов блокируются повторная загрузка и изменение параметров; навигация,
просмотр и фильтрация доступны. Все запросы имеют таймаут 60 секунд и явный
выход из состояния загрузки. Сбой модуля не скрывает успешные данные других.

В транзакциях — поиск, направление и пагинация по 25 строк, длинный текст
переносится, на узких экранах таблицы прокручиваются в своем контейнере.
Категории, источник правил и причины берутся из backend; JS не категоризирует.
Повторные группы фильтруются по статусу. Среднее, разброс, периодичность,
пригодность для расчета и даты показываются из существующей модели.

Обзор использует summary прогноза, не суммирует исторические деньги самостоятельно.
Отдельно подписаны исходный/конечный остатки и ожидаемые потоки за период.
Неизвестный баланс — «Нет данных»; ноль остается известным нулем. Форматирование
денежных строк использует BigInt для целой части без потери копеек/больших значений.
Для координат графика применяется Number как визуальное приближение; точные
значения доступны в таблице. Даты форматируются без сдвига часового пояса.

График использует daily.balance, а при неизвестном балансе — уже рассчитанный
backend cumulative_cash_flow. Клиент не восстанавливает абсолютный остаток из
нулевой базы. Пустые и неполные дневные данные отображаются явно. Прогноз
доступен по дням и категориям, ограничения раскрываются отдельным списком.

Разрывы: not_available, no_gaps, detected и ошибка запроса — четыре разных
состояния. При detected показаны все группы с датами, минимумом, дефицитом,
длительностью, восстановлением и контекстом существующих событий. Неизвестная
дата восстановления не подменяется. Нового алгоритма анализа на клиенте нет.

## Проверка датасетов

| Проверка в реальном браузере | C071.csv | C015.csv |
| --- | ---: | ---: |
| Операций после загрузки | 614 | 2455 |
| Ошибок пропуска ИНН показано | 5 | 96 |
| Категории/объяснения | показаны | показаны |
| Повторные группы | показаны | показаны |
| Дневных строк прогноза | 30 | 30 |
| Текущий срез: разрывы | анализ недоступен | анализ недоступен |
| Срез 2026-09-30: разрывы | не обнаружены | не обнаружены |

Проверены выбор файла, размер/имя, реальный POST, частичный импорт, таблица,
категории, переход на вторую страницу и source operation_id, поиск и направление,
повторяемость, SVG, изменение даты и известный баланс исторического среза.
На текущую дату (2026-10-24) исходные остатки неизвестны, потому что оба файла
заканчиваются 2026-09-30. Это корректно отражается в обзоре, графике и разрывах.

Также через браузер загружен временный XLSX с полным содержимым C071: все 614
исходных операций преобразованы только по формату файла, никакие финансовые
данные не придуманы. Оригинальных XLSX не предоставлено. Временный файл удаляется
после проверки, оригинальные CSV не меняются; SHA-256 проверяются до и после.

Фактических разрывов на исторических оригиналах нет. Отображение двух разрывов
(recovered/ongoing) проверено отдельным HTTP-fixture только в browser-тесте;
это не результат реальных датасетов и не production-заглушка. Аналогично отказы
endpoint, неполный JSON и вредоносный HTML в описании подменялись только тестовым
перехватом запросов, без изменения серверных операций.

Browser QA выполнен headless Microsoft Edge через Playwright. Проверены viewport
1440×1000 и 390×844, отсутствие горизонтального overflow страницы и визуальные
снимки. Изоляция ошибки 503 и повтор модуля проверены с остальными реальными
endpoints; неудачный импорт сохраняет предыдущие данные. Проверены пустое
пространство, некорректный/неполный ответ, безопасное отображение текста и
несколько разрывов. В Node-тестах дополнительно проверены сеть и таймаут.
Машиночитаемый результат — [sprint6_results.json](sprint6_results.json).

Ошибок в итоговых прогонах нет. Осталось прежнее предупреждение Starlette о
тестовом HTTPX. Lint, TypeScript и build не настроены и не запускались: новый
frontend — buildless HTML/CSS/JS, ему не требуется компиляция/сборка.
Другие браузеры и устройство с реальным touch-вводом не проверялись.

## Запуск, ограничения и статус

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload
```

Откройте http://127.0.0.1:8000/. Переменные окружения и отдельный frontend-сервер
не нужны: клиент использует относительные `/api` того же origin. Node/Playwright
нужны только для тестов; инструкции установки — в README.

Ограничения backend сохранены: одна последняя выписка в памяти, без разделения
пользователей. После обновления страницы GET возвращает операции, но не
сохраненное имя файла/отчет импорта/source_rows; интерфейс показывает это явно.
Новый механизм хранения не создавался. Открытие index.html через file://
не поддерживается: используйте FastAPI, чтобы относительные API работали.
Текущий неизвестный баланс не считается нулем или отсутствием риска.

Основной пользовательский сценарий Sprint 6 полностью реализован и проверен
на обоих оригиналах. Все необходимые endpoints доступны, блокирующих проблем
интеграции нет. Финансовые алгоритмы, модели хранения, авторизация банков,
платежные операции и функции следующих спринтов не добавлялись.
